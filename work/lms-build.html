( overview )

회계·세무 시험을 준비하는 수강생을 위한 온라인 교육 플랫폼입니다.
강의 구매부터 학습 기록 확인까지, 웹과 앱 화면을 만들었습니다.

  • [ Consistency ] 웹과 앱 화면 전반에
    같은 디자인 기준 적용
  • [ Seamless ] 강의 탐색부터 구매까지
    이어지는 흐름을 단순하게 구성
  • [ Differentiation ] 수강 현황과 성취도 데이터를
    시각화해 학습 현황을 한눈에 확인

디자인 시스템

컬러와 공통 컴포넌트의 기준을 정리해 웹과 앱에 공통 기준으로 적용했습니다.

( 01 )

강의 탐색부터 구매 결정까지

목표 시험별 강의 탐색을 시작하는 메인 홈

주요 프로모션과 시험별 대표 강의를 한눈에 확인하고 원하는 강의 탐색으로 이어질 수 있도록 구성했습니다.

원하는 강의를 찾고 정보를 확인하는 목록·상세 화면

강의 목록 화면에서는 과정·과목·강사 필터를 통해 조건에 맞는 강의를 빠르게 찾아볼 수 있습니다.
상세 화면에서는 강의 정보와 샘플 영상을 확인하고 교재 정보와 관련 종합반까지 한 페이지에서 함께 살펴볼 수 있도록 했습니다.

( 02 )

수강부터 학습 기록 확인까지

앱에서는 강의 수강과 문제풀이 응시, 학습 데이터 조회까지 할 수 있습니다.

QR코드로 출입하는 스터디랩

QR코드로 스터디랩에 출입한 기록은 학습 시간 데이터로 이어지고, 홈에서 전날 학습 시간과 스터디랩별 1등 기록을 확인할 수 있습니다.

풀이부터 분석까지, 학습의 전 과정을 담은 문제풀이 앱

기출·모의고사 응시부터 채점, 결과 및 해설 확인까지 학습 흐름이 이어지도록 구성했습니다.

  • 문항별 풀이 시간을 측정하고 권장 풀이 시간과 비교하며
    실전 감각을 익힐 수 있습니다.

  • 전체 문항의 풀이 여부를 한눈에 확인하고
    풀지 않은 문항으로 바로 이동할 수 있습니다.

  • 내 점수와 정답률, 문항별 채점 결과를 확인하고
    해설까지 이어서 볼 수 있습니다.

세 갈래의 학습 데이터를 하나의 리포트로

강의 수강, 스터디랩 출입, 문제풀이 데이터를 하나의 리포트에 모아 시각화했습니다.

( 03 )

디자인 설계부터 코드 구현까지

HTML과 SCSS로 반응형 웹을 퍼블리싱했습니다.
슬라이드는 Swiper와 Splide를, 간단한 인터랙션은 JavaScript를 사용했습니다.

  • 배포 후 브라우저에서 토큰명을 확인할 수 있도록 디자인 시스템 색상을 CSS 변수로 등록

  • display: none 대신 clip으로 기본 체크박스를 화면에서 숨기고 체크박스 기능은 유지하고 모양만 변경

( 04 )

회고

빠른 진행만큼 중요했던 결정의 기록

구축 초기 한 달 정도 기획 회의를 진행하는 동안, 팀 내에서 작업 시간을 확보하기 위해 별도 문서화 없이 진행하기로 했습니다. 확인이 필요한 내용은 팀원들과 그때그때 협의하며 진행했습니다. 당시에는 빠르게 진행할 수 있었지만 운영 기간이 길어지면서 '왜 이렇게 만들었는지', '언제 어떤 내용이 바뀌었는지'를 다시 확인하기 어려운 순간이 생겼습니다. 최소한 변경사항과 그 이유라도 기록해두었으면 좋았겠다는 아쉬움이 남았습니다. 다시 같은 상황이 온다면, 디자인 변경사항과 이유만큼은 따로 남겨둘 것 같습니다.

일정 준수를 위해 미룬 레이아웃 재검토

구축 중반 주요 데이터 구조가 바뀌었을 때, 마감 일정을 지키기 위해 화면 구조를 다시 검토하는 대신 기존 레이아웃을 유지하고 변경된 데이터만 반영했습니다. 운영을 시작한 뒤에는 데이터가 없거나 길이가 긴 경우, 일부 레이아웃이 안정적으로 대응하지 못하는 문제가 생겼고 다시 수정해야 했습니다. 지금 다시 작업한다면 데이터가 달라지는 경우까지 조금 더 넓게 확인한 뒤 화면 구조를 결정할 것 같습니다.
