( 04 )

회고

빠른 진행만큼 중요했던 결정의 기록

구축 초기 한 달 정도 기획 회의를 진행하는 동안, 팀 내에서 작업 시간을 확보하기 위해 별도 문서화 없이 진행하기로 했습니다. 확인이 필요한 내용은 팀원들과 그때그때 협의하며 진행했습니다. 당시에는 빠르게 진행할 수 있었지만 운영 기간이 길어지면서 '왜 이렇게 만들었는지', '언제 어떤 내용이 바뀌었는지'를 다시 확인하기 어려운 순간이 생겼습니다. 최소한 변경사항과 그 이유라도 기록해두었으면 좋았겠다는 아쉬움이 남았습니다. 다시 같은 상황이 온다면, 디자인 변경사항과 이유만큼은 따로 남겨둘 것 같습니다.

일정 준수를 위해 미룬 레이아웃 재검토

구축 중반 주요 데이터 구조가 바뀌었을 때, 마감 일정을 지키기 위해 화면 구조를 다시 검토하는 대신 기존 레이아웃을 유지하고 변경된 데이터만 반영했습니다. 운영을 시작한 뒤에는 데이터가 없거나 길이가 긴 경우, 일부 레이아웃이 안정적으로 대응하지 못하는 문제가 생겼고 다시 수정해야 했습니다. 지금 다시 작업한다면 데이터가 달라지는 경우까지 조금 더 넓게 확인한 뒤 화면 구조를 결정할 것 같습니다.
